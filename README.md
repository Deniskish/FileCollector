# FileCollector

Потокобезопасный сборщик файлов из чанков, приходящих в произвольном порядке
и с пересечениями. Header-only, C++20, без зависимостей (GTest — только для тестов).

## Сборка и тесты

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j
ctest --test-dir build --output-on-failure

# с ThreadSanitizer / AddressSanitizer (GCC/Clang)
cmake -S . -B build-tsan -DCMAKE_BUILD_TYPE=Debug -DFC_SANITIZER=thread
```

GoogleTest берётся из системы (`find_package`), иначе скачивается через FetchContent.

## Интерфейс

| Метод | Назначение |
|---|---|
| `CollectFile(id, size)` | Регистрирует файл, выделяет буфер один раз |
| `OnNewChunk(id, pos, chunk&&)` | Добавляет чанк; до `CollectFile` чанки буферизуются |
| `TryTakeFile(id)` | Полный файл перемещением, без копирования; `nullopt`, если не готов |
| `WaitAndTakeFile(id, timeout)` | То же с ожиданием завершения сборки |
| `ReadRange(id, pos, span)` | Частичное чтение уже полученного диапазона в буфер вызывающего |
| `GetReceivedRanges(id)` / `GetProgress(id)` | Что уже получено |

## Ключевые решения

**Хранение.** Буфер размера файла + набор слитых непересекающихся интервалов
`std::map<begin, end>`. Чанк вставляется за O(log k + m) (k — число «дыр»,
m — число перекрытых интервалов). Копируются только ещё не полученные байты,
поэтому пересечения и дубликаты не стоят лишних memcpy.

**Блокировки.** `shared_mutex` на таблицу файлов (эксклюзивно — только при
появлении нового id) + `mutex` на каждый файл. Под мьютексом файла чанк лишь
резервирует свои непокрытые участки; `memcpy` идёт без блокировки.
Зарезервированные участки не пересекаются, поэтому потоки пишут в один буфер
параллельно без гонок. Готовность определяется по фактически записанным байтам.

**Копирования.** Чанк принимается по `&&`, итоговый буфер отдаётся `move`.
Каждый байт файла копируется ровно один раз.

**Граничные случаи.** Чанки за границей файла (включая переполнение `pos + len`)
и пустые отбрасываются; повторный `CollectFile` игнорируется; после выдачи
файла опоздавшие дубликаты игнорируются, а id можно переиспользовать.

## Возможные улучшения

- Шардирование таблицы файлов при очень большом числе новых id.
- Отображение больших файлов в память (`mmap`) вместо `std::vector`.
- `ReadRange` сейчас копирует под мьютексом файла; при необходимости
  буфер можно держать в `shared_ptr` и копировать вне блокировки.
